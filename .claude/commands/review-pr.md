# PR レビュープロンプト

共通ルール（AI Platform の `prompts/coding-agent-typescript-python.md`、または対象プロジェクトに同期された共通ルール）と、プロジェクト固有の `AGENTS.md` / `CLAUDE.md` をあわせて適用する。レビューではコード変更を行わず、明示的に依頼された場合だけ別途修正を行う。

## 入力情報

- 対象リポジトリ、PR URL または番号
- PR の目的、関連 Issue、対象ブランチ
- 既存の設計・互換性・セキュリティ要件
- CI 実行 URL とテスト結果（あれば）
- 特に確認したい観点（あれば）

## 作業手順

1. PR 本文、関連 Issue、変更差分、変更前後の関連コード、テスト、CI 結果を確認する。
2. 要求・既存設計・公開契約と差分を照合する。
3. 正しさ、境界条件、例外処理、型安全性、入力検証、テスト十分性を確認する。
4. 認証・認可、Secret、個人情報、DB 操作、公開 API、依存関係、CI 権限に対する影響を確認する。
5. 互換性、性能、運用、ロールバック容易性を評価する。
6. 指摘は重要度順に、再現条件・根拠・推奨修正を添えて報告する。問題がなければ、確認した範囲と残るリスクを明記する。

## 完了条件

- 品質、セキュリティ、互換性を含むレビュー結果が根拠付きで整理されている。
- 指摘ごとにファイル・箇所、影響、推奨対応が分かる。
- 実行していない検証や確認できなかった範囲が明記されている。

## 禁止事項

- 差分を読まずに一般論だけで指摘しない。
- 重大度を誇張せず、再現性や影響が不明な点は推測として扱う。
- Secret、個人情報、ログ全文を報告しない。
- レビュー依頼だけの場合、無断でコード・設定・PR 状態を変更しない。

## 報告形式

```md
## レビュー結果
結論: Approve / Changes requested / Comment

## 指摘事項
1. [重大度: Critical / High / Medium / Low] `<path>:<line>`
   - 問題: <内容>
   - 影響: <内容>
   - 根拠・再現条件: <内容>
   - 推奨対応: <内容>

## 確認した内容
- <設計、テスト、CI など>

## 未確認事項・残存リスク
- なし / <内容>
```
