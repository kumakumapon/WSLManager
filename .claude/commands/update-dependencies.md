# 依存関係更新プロンプト

対象リポジトリの依存関係を、プロジェクトの更新方針、互換性、ライセンス、脆弱性、ロックファイルを確認したうえで安全に更新する。

## 依頼形式

```text
依存更新 owner/repo [セキュリティ] [PR作成]
```

`セキュリティ` は、修正済みバージョンが確認できるセキュリティ更新を優先する指定である。`PR作成` がある場合だけ、変更を作業ブランチに作成し、ドラフト Pull Request を作成する。

## 手順

1. `AGENTS.md`、依存マニフェスト、ロックファイル、パッケージマネージャー、CI、更新bot設定、ライセンス方針、既存Issue/PRを確認する。
2. 利用中の依存関係、直接・推移依存、サポート状況、既知の互換性制約、利用可能な脆弱性情報を調査する。`セキュリティ` 指定時も、未検証の報告を脆弱性として断定しない。
3. 影響範囲が明確で検証可能な更新だけを選ぶ。原則として最小の互換バージョンにとどめ、メジャー更新、未保守化、ライセンス変更、公開APIやビルド挙動への影響は別提案に分ける。
4. パッケージマネージャーで正規にロックファイルを更新し、変更前後の依存ツリーを確認する。手編集、不要な一括更新、不要な依存追加は行わない。
5. 該当する lint、型チェック、テスト、ビルド、脆弱性スキャンを実行する。修正手段がない懸念や公開すべきでない詳細は、Security Policy に従う非公開の報告経路へ案内する。

## 完了基準

- 各更新について、目的、変更範囲、互換性・ライセンス・セキュリティの確認結果が記録されている。
- テスト・ビルド等の結果と未実施理由が区別されている。
- `PR作成` がある場合だけ、依存更新を他の無関係な変更と混ぜずドラフト PR にしている。

## 報告

更新した依存関係、選定理由、保留した更新、検証結果、利用者影響、未解決の懸念、PR URLを日本語で報告する。
