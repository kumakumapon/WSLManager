# セキュリティ調査プロンプト

対象リポジトリのセキュリティ上の懸念を、公開可能な情報だけで慎重に調査する。コード、設定、Issue、PR、Releaseは変更・作成しない。

## 依頼形式

```text
セキュリティ owner/repo [調査]
```

`調査` は省略できる。この依頼は読み取り専用であり、公開Issue、公開PR、再現手順、攻撃コード、Secret、個人情報を作成・出力しない。

## 調査手順

1. `SECURITY.md`、Security Policy、`AGENTS.md`、README、依存マニフェストとロックファイル、認証・認可境界、入力検証、秘密情報の扱い、CI/デプロイ設定、既存のセキュリティ通知を確認する。
2. 認証・認可、外部入力、データ露出、依存関係、権限、Secret、ログ、CI、サプライチェーン、公開設定を、実装と設定に基づいて確認する。
3. 所見を「確認済みの対策」「追加確認が必要な点」「非公開で扱うべき懸念」に分ける。悪用可能な詳細、正確な脆弱箇所、攻撃手順、認証情報はチャット、Issue、PR、コミットに含めない。
4. Security Policy または私的な報告経路がある場合は、その連絡先・手順を優先する。非公開報告経路がない場合は、リポジトリ管理者に非公開チャネルで共有するよう案内する。
5. 修正の実装、依存更新、公開Issue/PR、脆弱性の公開は、この依頼の範囲外とする。修正が必要な場合は、公開前に管理者の方針と報告経路を確認する。

## 報告基準

- 公開可能な報告は、全体の成熟度、確認範囲、一般化した改善領域、次の安全な手順だけにとどめる。
- 重大度は確証に比例させ、根拠が不足する懸念を脆弱性として断定しない。
- 非公開で扱うべき発見がある場合は、その内容をチャットに記載せず「非公開報告が必要」とだけ伝える。

## 報告

確認範囲、確認済みの対策、一般化した改善領域、非公開報告の要否、安全な次の手順を日本語で報告する。
