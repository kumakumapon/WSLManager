# Issue 実装プロンプト

共通ルール（AI Platform の `prompts/coding-agent-typescript-python.md`、または対象プロジェクトに同期された共通ルール）と、プロジェクト固有の `AGENTS.md` / `CLAUDE.md` をあわせて適用する。

## 入力情報

- 対象リポジトリ、対象 Issue の URL または番号
- Issue の目的、完了条件、優先度
- 変更可能・変更禁止の範囲
- 関連する PR、設計資料、CI 実行 URL（あれば）
- ブランチ・PR 作成に関する指示

入力が不足している場合は、リポジトリと Issue を調査し、実装を左右する不明点だけを確認する。

## 作業手順

1. Issue、プロジェクトの `AGENTS.md`、関連コード、設定、既存テストを読んで、現状と完了条件を整理する。
2. 変更対象、互換性・セキュリティ上の影響、追加または更新するテストを決める。影響が大きい不明点は実装前に報告する。
3. 整理した完了条件・変更対象・実装方針を、要求との整合性・見落とし・実現性の観点でレビューする。Critical または High 相当の懸念（要求との齟齬、認証・認可・DB・公開APIへの根拠のない変更、実現不可能な前提など）がある場合は、解消するまで手順1〜3を繰り返してから実装に進む。
4. 既存設計に沿い、要求を満たす最小限の変更を実装する。
5. 不具合なら回帰テスト、機能なら重要な成功・失敗ケースのテストを追加または更新する。
6. lint、型チェック、テスト、ビルドのうちプロジェクトで定義された検証を実行し、失敗時は原因を調査して必要最小限の修正を行う。
7. 差分を `prompts/review-pr.md` と同じ観点（正しさ・境界条件・例外処理・型安全性・入力検証・認証認可・Secret・互換性・性能・運用・テスト十分性）でレビューする。Critical または High 相当の指摘がある場合は対応し、指摘がなくなるまで手順4〜7を繰り返してから完了とする。
8. 指示がある場合は、レビュー結果を含む内容が分かる PR を作成する。

## 完了条件

- Issue の明示された完了条件を満たす。
- 変更が最小限で、関連する自動テストまたは代替検証がある。
- 実行した検証とその結果が記録され、未実施項目は明示されている。
- PR を作成する指示がある場合、変更内容・テスト結果・リスクを含む PR が作成されている。

## 禁止事項

- Issue 本文だけを根拠に周辺仕様を推測して変更しない。
- テストや品質チェックを削除・無効化・skip して通過させない。
- Secret、個人情報、実運用データを出力・コミットしない。
- 認証、認可、DB、公開 API を明示的な根拠なく変更しない。
- 未実施の検証を成功と報告しない。

## 報告形式

```md
## 実装概要
- Issue: <URL または番号>
- 対応内容: <要約>

## 変更ファイル
- `<path>`: <変更理由>

## 検証
- `<command>`: 成功 / 失敗 / 未実施（理由）

## 影響・リスク
- <互換性、運用、セキュリティ上の注意>

## セルフレビュー
- 計画: なし / [重大度: Critical / High / Medium / Low] <指摘と対応>
- 差分: なし / [重大度: Critical / High / Medium / Low] <指摘と対応>

## 残課題
- なし / <内容>

## PR
- <URL または未作成理由>
```
