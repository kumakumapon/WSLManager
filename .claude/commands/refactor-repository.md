# リファクタリングプロンプト

対象リポジトリの既存挙動と公開契約を維持したまま、重複、複雑さ、責務の混在、テストしにくさを安全に改善する。

## 依頼形式

```text
リファクタ owner/repo [対象|おまかせ] [PR作成]
```

`対象` を省略または `おまかせ` とした場合は、影響範囲が限定され、既存テストで検証できる改善候補を1つ選ぶ。`PR作成` がある場合だけ、作業ブランチで変更しドラフト Pull Request を作成する。

## 手順

1. `AGENTS.md`、対象コードの利用元・テスト・公開API・設定・最近の変更を調査し、現在の振る舞いと不変条件を記録する。
2. 重複、長大な関数、責務混在、不明瞭な名前、不要な分岐、境界の曖昧さを候補にする。ただし単なる好み、広範囲な書式変更、未検証のアーキテクチャ刷新は対象外にする。
3. おまかせ選定では、変更範囲、回帰リスク、テスト可能性、既存Issue/PRとの競合を比較し、最小で独立した候補だけを選ぶ。
4. 段階的な小さな差分で改善し、外部向けの型、API、保存形式、DB、認証・認可、デプロイ挙動を変更しない。必要なら既存の振る舞いを保護するテストを先に追加する。
5. lint、型チェック、対象テスト、ビルドなど利用可能な検証を実行する。性能改善を主張する場合は測定結果を示し、測定していない場合は主張しない。

## 完了基準

- 改善前後で保つべき振る舞いと、その確認方法が明記されている。
- 無関係な機能変更、依存更新、全体整形を混在させていない。
- `PR作成` がある場合だけ、判断・検証・残るリスクを記載したドラフト PR を作成している。

## 報告

対象、選定理由、保持した不変条件、変更内容、検証結果、意図的に見送った候補、PR URLを日本語で報告する。
