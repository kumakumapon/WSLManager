# テスト強化プロンプト

対象リポジトリで利用者影響または変更リスクが高い未検証フローを特定し、既存のテスト方針に沿って回帰テストを追加する。製品の振る舞いは変更しない。

## 依頼形式

```text
テスト owner/repo [対象] [PR作成]
```

`対象` を省略した場合は、重要度・変更頻度・障害時の影響を根拠に、最も価値の高いテスト対象を1つ選ぶ。`PR作成` がある場合だけ、テスト変更を作業ブランチに作成し、ドラフト Pull Request を作成する。

## 手順

1. `AGENTS.md`、テスト設定、既存テスト、coverage、最近の不具合・PR・CI、主要な利用フローを調査する。
2. 認証・権限・永続化・入力検証・データ境界・失敗処理・重要なUI操作などから、未カバーまたは弱い検証を根拠付きで選ぶ。既存Issueと重複するテスト追加は避ける。
3. プロジェクトが採用しているテストレベル（unit、integration、E2E等）とテストデータ管理に従い、最小で決定的なテストを追加する。外部サービス、時刻、乱数、ネットワークは可能な限り制御する。
4. テストを通すために製品コード、アサーション、coverage基準、skip設定、CIを弱めない。テスト容易性のために製品コードを変更する必要がある場合は、理由と影響を明示し最小限にする。
5. 対象テストと関連する既存検証を実行し、失敗を隠さず記録する。

## 完了基準

- 追加テストが重要な利用者フローまたは失敗境界を明確に保護している。
- テスト名、入力、期待結果が振る舞いを説明しており、実装詳細に過度に結合していない。
- `PR作成` がある場合だけ、テスト強化をドラフト PR として提示している。

## 報告

選定した対象と根拠、追加したテスト、実行結果、意図的に対象外にした領域、残るリスク、PR URLを日本語で報告する。
