# TypeScript / Python Coding Agent Common Rules

この文書は、TypeScript と Python を使う各プロジェクトで共通利用するコーディングエージェント向けの基準です。プロジェクト固有の `AGENTS.md`、Issue、PR の指示がある場合は、それらを優先してください。

## 基本姿勢

- 既存のアーキテクチャ、命名、責務分割、依存関係を調査して尊重する。必要性が明確でないリファクタリングや依存追加はしない。
- 要求を満たす最小限の差分で実装する。変更範囲と互換性への影響を明確にする。
- 実装前に、関連する実装、設定、テスト、呼び出し元、公開インターフェースを調査する。不明点を推測で補わず、確認またはリスクとして報告する。
- 外部入力（HTTP リクエスト、環境変数、ファイル、Webhook、CLI 引数、DB の非信頼データ）を境界で検証する。

## 言語別の基準

### TypeScript

- `any`、不安全な型アサーション、暗黙の `undefined` 依存を避け、型安全性を優先する。
- 入出力の型を明示し、外部データは型ガードまたはスキーマ検証を経て扱う。
- 既存の TypeScript 設定と lint ルールに従い、公開 API の型変更は互換性を確認する。

### Python

- 新規または変更した関数・メソッドには、読みやすい型ヒントを付ける。
- 予測可能な失敗は、原因と対処が分かる明確な例外処理にする。例外を広く握りつぶさない。
- 外部データを検証し、リソースはコンテキストマネージャー等で確実に解放する。

## 品質と検証

- 不具合修正には、修正前に失敗し修正後に成功する回帰テストを追加する。テストが追加できない場合は理由と代替検証を記録する。
- プロジェクトで定義された lint、型チェック、テスト、ビルドを実行する。未実施・失敗・環境上実行不能の検証を成功として報告しない。
- テスト削除、アサーション緩和、skip 追加、lint/型チェック/CI の無効化によって問題を回避しない。

## セキュリティと変更境界

- Secret、アクセストークン、個人情報、認証情報をログ、テスト出力、コミット、PR 本文に出力しない。必要な例は必ずマスク済みのダミー値にする。
- 認証、認可、データベーススキーマやデータ保持、公開 API、決済、デプロイ設定は、要件または既存仕様を確認せずに推測で変更しない。
- 依存パッケージの追加・更新は、必要性、ライセンス、脆弱性、既存の代替手段を検討して最小限にする。

## PR と報告

- PR には、変更内容、実装上の判断、実行したテストと結果、影響範囲、リスク、未検証事項を記載する。
- 事実・実行結果・推測を区別して報告し、未解決事項を隠さない。
